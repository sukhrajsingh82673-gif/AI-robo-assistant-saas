# ZONATA UNIVERSAL AI COMPANY OPERATING SYSTEM
## Production Runtime Gap Matrix (Phase 0 Baseline)

| Component | Current Assumption | Distributed Risk | Target Architecture | Migration Required | Test Required | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Relational Database (`core/db.py`)** | Local filesystem SQLite (`storage/roboassistant.db`) with WAL mode. | File lock contention across multiple host nodes; cannot scale horizontally across pods. | Database abstraction layer supporting authoritative PostgreSQL with connection pooling & transaction timeouts; SQLite retained for local/CI tests. | Implement `DatabaseEngine` abstraction, PostgreSQL migrations, schema compatibility layer. | Concurrent multi-node connection pool test & migration verification test. | IDENTIFIED |
| **Evidence Ledger (`core/evidence_ledger.py`)** | Local `audit_ledger.jsonl` locked via kernel `fcntl.flock`. | `fcntl` is node-local; concurrent writes from separate Kubernetes pods will corrupt or diverge ledger. | Distributed `EvidenceService` backed by transactional PostgreSQL table `merkle_evidence_events` with sequence numbers & SHA-256 chaining; S3 object store for binary payloads. | Implement transactional event append API with distributed hash verification. | Multi-node concurrent append and hash continuity test. | IDENTIFIED |

| **Distributed Coordination & Caching** | Local in-memory dictionaries & file locks. | Inconsistent state across replicas; duplicate executions; race conditions in quota checks. | Distributed Redis / coordination layer for distributed locks, lease management, rate limits, and short-lived caching. | Implement Redis coordination protocol with automatic fallback and circuit breaking. | Distributed lock expiration, renewal, and mutual exclusion test. | IDENTIFIED |
| **Central Action Gateway** | Subsystems (Browser Use, OpenHands, MCP, Nango, Temporal) execute via separate gateways. | Potential governance divergence; inconsistent policy/authority checks across execution planes. | Unified `ZonataActionGateway` routing ALL external mutations through the canonical 20-step execution pipeline. | Unify dispatch pipeline across all 10 project adapters with standard `ActionEnvelope`. | Universal action pipeline security and policy rejection test. | IDENTIFIED |
| **Agent Workforce Resource Governor (`core/agent_factory_runtime.py`)** | SQLite-backed quotas (`tenant_agent_quotas`) evaluated per node. | Cross-node race conditions allowing tenant quota oversubscription during simultaneous agent spawning. | Distributed `AgentResourceGovernor` enforcing tenant token, concurrency, spend, and delegation budgets across all nodes. | Implement admission control, queueing, and distributed quota decrement. | 1,000 simulated agent quota exhaustion & concurrency limit test. | IDENTIFIED |
| **Agent Factory & Tool Factory (`core/agent_factory_runtime.py`)** | AST-based static code scanning on local filesystem; in-process mock evaluation. | Malicious tools executing on host control plane; lack of behavioral dynamic sandboxing. | `AgentFactoryV2` with immutable semantic versioning and `AgentEvaluationEngine`; `ToolFactoryV2` running non-root container sandboxes. | Implement immutable agent packages, promotion gates, and container execution policies. | Poisoned tool rejection test and agent evaluation gate test. | IDENTIFIED |

| **Secret Management (`core/secrets.py`, `core/credential_broker.py`)** | Local encrypted environment variables and file tokens. | Secret leakage to worker logs, database dumps, or prompt contexts. | Production `CredentialBroker` with KMS/Vault integration, ephemeral JIT leasing, zero-secret logging, and strict redaction. | Implement secret scanner, automatic redaction filter, and ephemeral lease manager. | Secret redaction test across logs, evidence, and prompts. | IDENTIFIED |

| **Observability & SLO Management** | In-process logging and basic `/health` JSON endpoint. | Inability to correlate traces across multiple distributed nodes; indistinguishable synthetic vs real metrics. | Distributed OpenTelemetry-compatible tracing with `request_id`, `correlation_id`, `causality_id`, and strict metric partitioning (REAL vs SIMULATED). | Implement structured telemetry engine, distributed tracing headers, and SLO monitors. | Metric classification audit and trace propagation test. | IDENTIFIED |
