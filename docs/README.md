## Status vocabulary

Documents in this tree use the same status words as the release reports. They are not
interchangeable, and a document that says "implemented" is not claiming "verified".

| Status | Meaning |
|---|---|
| **Verified** | Executed against the real system, with retained evidence that can be re-run. |
| **Implemented, unverified** | Code exists and is wired in, but the end-to-end behaviour has not been proven. |
| **Partial** | Some of the capability works; the remainder is explicitly listed as missing. |
| **Blocked** | Cannot progress in this environment (missing runtime, credentials, or infrastructure). |
| **Not implemented** | No code path exists. |
| **Failed** | Executed and did not meet the requirement. |

## Naming

Two naming eras coexist. `V3`–`V10` and `PROJECT_10`/`GEMMA4`/`AIC` prefixes are the version-series
evidence of earlier releases and are kept verbatim so that historical references stay resolvable.
Unprefixed names describe the current capability. The ordered `01_`–`30_` set in `architecture/`
is the current production design series and is meant to be read in order.
