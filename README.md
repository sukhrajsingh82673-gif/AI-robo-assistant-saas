  - `IMMEDIATE`: Real-time anomalies, outages, payment failures
  - `TODAY`: Daily operating missions, night audit, reconciliations

  - `LONG_TERM`: Quarters/years (platform evolution, market expansion)

## 🔒 Constitutional Security Invariants

1. **Capability != Authority**: Having access to a tool or discovery of an executable never grants permission to invoke it without an authorized contract.
2. **Credential Isolation**: Secrets are vaulted; agents only receive opaque handles (`cred_...`).
3. **MFA Integrity**: MFA requirements enter `WAITING_FOR_OWNER` and cannot be bypassed.
4. **Sandbox Path Isolation**: Desktop robot mutations are strictly bounded to designated workspaces.
5. **No Auto-Execution of Untrusted Data**: External downloads and customer content are treated strictly as data.
6. **Task Success != Business Outcome**: Verified commercial transactions are required before recognizing revenue.
7. **Workflow State != Authority**: Resuming a checkpoint or transitioning graph nodes never inherits or bypasses ZONATA approval and policy gates.
8. **Checkpoint != Evidence**: Storing an intermediate or terminal execution state in SQLite is not business evidence; evidence requires cryptographic Merkle ledger sealing.
9. **Graph Definition != Permission**: Defining an edge or cycle in a `StateGraph` does not authorize side effects or external mutations.
10. **Model Output != Authorization**: An agent deciding to branch or iterate within a graph must still submit high-risk actions to the ZONATA Authority Gateway.
11. **Retry != Safe Replay**: Non-idempotent operations are blocked from automated replay; ambiguous outcomes require state reconciliation.
12. **Zero-Secret Persistence in Checkpoints**: Thread state checkpointers scrub all API tokens, bearer keys, and plaintext secrets before writing to disk.
13. **A2A Message != Authority**: Receiving an A2A message, task request, or delegation never conveys authority or permission to perform local mutations.
14. **Agent Card != Trust**: External Agent Cards (`/.well-known/agent-card.json`) are untrusted external inputs requiring strict schema validation, sanitization, and reputation bootstrapping.
15. **External Response != Truth**: Claims returned in remote A2A responses are treated strictly as untrusted observation data until independently verified against physical evidence.
16. **External Request != Authorization**: Actions requested by external agents on local resources must be authenticated, policy-checked, and approved by ZONATA authorities before execution.
17. **A2A Task Completion != Business Outcome**: A remote task reporting `TASK_STATE_COMPLETED` does not count as business success; commercial revenue recognition requires cryptographic causality verification.
18. **Zero-Secret Outbound Exposure**: Data minimization and regex secret scrubbing strip API keys, tokens, session IDs, internal DB schemas, and employee identities from outbound messages.
19. **Ambiguous Remote State Reconciliation**: Ambiguous remote mutations enter an explicit `AMBIGUOUS` state requiring deterministic reconciliation without blind automated replay.
20. **Authoritative KillSwitch Override**: Global or tenant KillSwitch immediately halts all inbound and outbound A2A communication, severing untrusted agent connections.
21. **Epistemic Memory Separation**: External agent communication is quarantined from internal Letta agent identity blocks (`persona`, `human`); untrusted inputs are never written directly into agent self-prompts.
22. **OpenHands Agent != Authority**: The agent execution runtime is an execution worker, never an autonomous authority or decision-making layer.
23. **OpenHands Tool != Permission**: Availability of bash execution, file editing, or tools does not convey business permission.
24. **Workspace != Trusted Environment**: Sandboxes and repositories are untrusted workspaces; all files and dependencies are subject to security scanning and isolation.
25. **Terminal Access != Authorization**: Executing a command requires risk classification; dangerous system commands are forbidden and privileged commands require human approval.
26. **File Access != Permission**: All file operations are constrained to the assigned workspace directory; path traversal (`../`) and symlink escapes are strictly blocked.
27. **Code Execution != Business Authorization**: Running code or building artifacts is strictly an operational step, never an authorized business transaction.
28. **Agent Decision != Policy Decision**: Agent internal reasoning or planning cannot override ZONATA policy rules, spending limits, or tenant boundaries.
29. **Agent Success != Business Success**: A completed agent run does not constitute business outcome achievement.
30. **Command Success != Desired Outcome**: An exit code of 0 does not prove that the intended business outcome was satisfied.
31. **Generated Code != Verified Code**: Synthesized code must undergo independent physical reality verification before being accepted.
32. **Test Pass != Production Safety**: Passing local tests in a workspace does not authorize deployment or merging into production branches without human governance approval.
33. **Workspace State != Evidence**: Files resting on disk in a workspace do not constitute audit evidence; evidence requires cryptographic Merkle ledger sealing.
34. **Browser Use != Authority**: Browser automation is an execution instrument, never an independent business authority or decision-maker.
35. **Browser Session != Permission**: Holding an active browser session does not authorize navigating to unapproved endpoints or executing arbitrary interactions.
36. **Login Session != Business Authorization**: An authenticated web portal session or stored cookie does not authorize financial, commercial, or privileged mutations without ZONATA governance approval.
37. **Click != Permission**: Ability to interact with a button or hyperlink (`element.click()`) does not convey permission to perform the underlying real-world action.
38. **Form Submission != Business Success**: Successful HTTP POST or form dispatch does not prove the intended commercial outcome occurred.
39. **DOM Text != Truth**: Text retrieved from a web page DOM is untrusted external perception data, subject to prompt-injection neutralization and independent verification.
40. **Prompt Injection Defense**: Adversarial commands embedded within web content (`"ignore previous instructions and..."`) are treated strictly as passive data and stripped of execution power.
41. **SSRF Defense Invariant**: Browser navigation is strictly prohibited from accessing internal loopbacks (`127.0.0.1`), RFC1918 private subnets, cloud metadata endpoints (`169.254.169.254`), or local file schemes (`file://`).
42. **Human-in-the-Loop Financial Escalation**: Any web action involving checkout, payment processing, price alteration, refund issuance, or legal contracts immediately halts in `AWAITING_APPROVAL` status.
43. **Non-idempotent Web Action Reconciliation**: Web requests with ambiguous connection outcomes (timeouts, network drops) are marked `RECONCILIATION_REQUIRED` and prohibited from automatic repeated re-execution.
44. **Authoritative Browser KillSwitch**: Multi-scope killswitches (Global, Tenant, Company, Session, Execution, Domain, Agent) instantly terminate active browser processes, disconnect contexts, and reject pending commands.
45. **Cryptographic Merkle Sealing**: Every completed browser execution, action sequence, and visual artifact must be sealed into the tamper-evident Merkle Evidence Ledger with SHA-256 proofs before outcome attestation.
